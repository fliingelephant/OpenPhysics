# Design

Single source of truth for the registry format. Skills and the CLI follow this file.

## Entry

One directory per problem, one file:

```text
problems/N/PROBLEM.md
```

`N` is a global counter in order of addition, written as a plain integer with no
padding. Numbers are minted at merge and never reused. An entry is never
deleted; it changes `<status>`.

File shape:

````markdown
# 45 Name

```xml
<problem id="45">
  <status>open</status>
  <kind>proof</kind>
  <field>QTD</field>
  <name>Name</name>
  <keys>lowercase retrieval terms and aliases</keys>
  <related>12 60</related>

  <claim>...</claim>
  <def>...</def>
  <known>...</known>
  <refs>
    <ref>...</ref>
  </refs>
  <ask>...</ask>
  <out>...</out>
</problem>
```
````

The heading id and name equal `<problem id>` and `<name>`. Tags appear in this
order. `<related>` is optional; every other tag is required.

Mathematics is LaTeX. XML text contains no raw `<`, `>`, or `&`; use `\lt`,
`\gt`, or entities.

## Tags

| tag | value |
|---|---|
| `status` | `open` or `solved` |
| `kind` | `proof` or `construction`, see below |
| `field` | one of `QIT`, `QCT`, `QTD`, `QMB`, see below |
| `name` | title, equals the heading |
| `keys` | space-separated lowercase retrieval terms; no ids |
| `related` | space-separated ids of existing entries; one direction suffices |
| `claim` | one mathematical assertion with all quantifiers; the source of truth |
| `def` | local definitions of every symbol in `claim` |
| `known` | proved facts, conjectures, and variants, each with its source named |
| `refs` | one `<ref>` per source: authors, title, venue, year, DOI or arXiv id, exact location used |
| `ask` | exact success condition, see kind |
| `out` | allowed return values, see kind |

## Kind

Kind is the deliverable.

- `proof`: the solver returns a proof of `<claim>` or of its negation. Existence
  statements, characterizations, inequalities, sharp constants, and rates are
  all `proof`. `<ask>` states the exact proof and disproof conditions.
  `<out>`: `proof`, `disproof`, `gap`, `progress`.
- `construction`: the solver returns an explicit object that a stated check
  accepts. `<claim>` cites the existence theorem and states the explicit family
  wanted. `<ask>` defines "explicit" and gives a finite verification procedure.
  `<out>`: `construction`, `gap`, `progress`.

## Field

One primary field per entry. Finer topics go in `keys`.

| code | scope |
|---|---|
| `QIT` | entanglement, nonlocality, communication, cryptography, tomography, metrology, Gibbs-state structure |
| `QCT` | complexity, proof systems, error models, codes, Hamiltonian complexity |
| `QTD` | resource theories, catalysis, thermal machines, Landauer and cooling limits |
| `QMB` | many-body: area laws, Lieb-Robinson, spectral gaps, thermalization |

A field splits only when a subarea passes about 30 entries.

## Solved

`<status>solved</status>`, one sentence in `<known>` stating the answer, one
`<ref>` to the proof. Nothing else changes.

## Sources

Cite by DOI or arXiv id. The repository stores no PDFs.

## Tool

`openphysics-cli`, Rust, in `tools/openphysics-cli/`. Plain-text output, stable
ordering, no network.

| command | result |
|---|---|
| `list [--field F] [--status S] [--kind K]` | one line per entry: id, field, name |
| `show ID [TAG]` | the entry, or one tag |
| `grep TERM` | ids whose keys, name, or claim match |
| `check` | validate every entry against this file; non-zero exit with `file:line` |
| `next` | next unused id |
| `index` | regenerate `problems/README.md` |

## Layout

```text
problems/   entries; README.md is generated by `index`
docs/       this file
skills/     agent workflows: add, review
tools/      openphysics-cli
AGENTS.md   agent instructions; CLAUDE.md is a symlink to it
LICENSE     MIT
```
